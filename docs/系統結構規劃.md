# 系統結構規劃

多平台電商的個人工作台（輕量 ERP）。
使用者：倉庫助理，在職期間個人使用。程式碼使用權歸開發者，資料歸公司。

---

## 1. 目標與範圍

### 要解決的問題

| # | 痛點 | 對應模組 |
|---|---|---|
| 1 | 四平台（蝦皮、露天、奇摩拍賣、酷澎）上架、庫存要分別處理 | 上架模組、批次檔匯出 |
| 2 | 拆賣商品（膠條：一車份／前後左右單賣）庫存不同步 | 組合商品計算 |
| 3 | 雜事多、指令散，容易漏做 | 任務收件匣 |
| 4 | 缺貨提醒被蝦皮訊息淹沒 | 叫貨清單 |
| 5 | 包貨出貨偶爾出錯 | 掃碼出貨核對 |
| 6 | 四層樓透天倉庫找不到貨 | 儲位系統 |
| 7 | 訂單要逐一開 App 確認 | 訂單匯入、統一待出貨清單 |

### 明確不做（本階段）

- **不串平台 API**。資料進出一律透過各平台後台的 Excel 匯出／匯入。
- **不自動回寫平台**。系統只產生批次更新檔，由使用者檢查後手動上傳。
- **不存顧客個資**。姓名、電話、地址、Email 在瀏覽器端解析時就丟棄，不送到伺服器。
- 不做會計、金流、發票。

### 最小驗證版本（MVP）

只做「蝦皮 × 膠條」一個完整循環：

1. 建立膠條部件 SKU 與一車份組合
2. 匯入蝦皮訂單 Excel
3. 自動扣庫存、重算一車份可售量
4. 產生蝦皮批次更新檔
5. 上傳後確認平台數量正確

此循環穩定運行一至兩週後，再擴充商品範圍與其他平台。

## 3. 系統形態

- 一個網站，以 PWA 形式安裝到手機主畫面，全螢幕開啟。
- **手機優先**：首頁、找貨、出貨、上架。單手操作。
- **電腦輔助**：訂單匯入、批次檔匯出、大量建檔、文案編修。
- 同一網址，依螢幕寬度切換版型（見 `design.md`）。

### 離線策略

- 商品、SKU、儲位、庫存快照：Service Worker 快取，**離線可查**（四樓、鐵皮屋訊號不穩）。
- 寫入動作（出貨核對、盤點調整、任務）：離線時存入 IndexedDB 佇列，連線後依序送出。
- 訂單匯入、批次檔匯出：需連線。

## 4. 資料模型

所有庫存變動都寫入 `stock_movements`，`skus.stock` 是快取值，可由異動紀錄重算。

### locations 儲位

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | integer PK | |
| code | text unique | 例：`1F-A-03`、`3F-L-02`、`4F-S-01`、`4F-T-05` |
| floor | text | `1F` / `3F` / `4F` |
| zone | text | `A`（一樓前段）、`L`（三樓左房）、`S`（神明廳）、`T`（鐵皮屋）等 |
| description | text | 補充說明 |

二樓不列為儲位。

### products 商品

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | integer PK | |
| name | text | |
| category | text | 汽車用品、工具、收藏品… |
| notes | text | 使用者的重點筆記 |
| weight_g | integer | |
| length_cm / width_cm / height_cm | real | |
| created_at / updated_at | datetime | |

### skus 可售單位

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | integer PK | |
| code | text unique | 自訂貨號，四平台的「規格貨號」都填這個 |
| product_id | FK products | |
| variant_name | text | 例：前左、一車份 |
| is_bundle | boolean | 組合商品不持有實體庫存 |
| stock | integer | 實體庫存快取；組合商品為 null |
| safety_stock | integer | 低於此值進入叫貨清單 |
| location_id | FK locations | |
| barcode | text | 可與 code 相同 |
| status | text | `active` / `archived` |

### bundle_components 組合關係

| 欄位 | 型別 | 說明 |
|---|---|---|
| bundle_sku_id | FK skus | 例：一車份 |
| component_sku_id | FK skus | 例：前左 |
| qty | integer | 一個組合需要幾個此部件 |

**組合可售量** = `min( floor(部件庫存 / qty) )`，即時計算，不存。
賣出組合商品時，扣的是各部件的庫存。

### platform_listings 平台對應

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | integer PK | |
| sku_id | FK skus | |
| platform | text | `shopee` / `ruten` / `yahoo` / `coupang` |
| platform_item_id | text | 平台商品編號 |
| platform_variant_id | text | 平台規格編號（若有） |
| last_pushed_stock | integer | 上次批次檔寫入的數量 |
| last_pushed_at | datetime | |

「待更新平台庫存」= 目前可售量 ≠ `last_pushed_stock` 的所有列。

### stock_movements 庫存異動

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | integer PK | |
| sku_id | FK skus | 只會是實體 SKU（非組合） |
| delta | integer | 正數入庫、負數出庫 |
| reason | text | `order` / `cancel` / `restock` / `return` / `damage` / `owner_take` / `adjust` / `initial` |
| ref_type | text | `order_item` / `import_batch` / `manual` |
| ref_id | text | |
| note | text | |
| created_at | datetime | |

`unique(ref_type, ref_id, sku_id, reason)`：同一筆訂單重複匯入不會重複扣庫存。

### orders / order_items 訂單（不含個資）

orders：`id`、`platform`、`platform_order_no`、`status`、`ordered_at`、`import_batch_id`
`unique(platform, platform_order_no)`

order_items：`id`、`order_id`、`sku_id`（可為 null）、`raw_sku_code`、`raw_name`、`qty`、`matched`（boolean）

- 匯入時以 `platform_order_no` upsert。
- 狀態由「未出貨」變成「已取消」時，寫入一筆 `cancel` 異動把庫存加回。
- 對不到 SKU 的品項標記 `matched = false`，在匯入結果頁列出，讓使用者手動對應。

### import_batches 匯入紀錄

`id`、`platform`、`filename`、`row_count`、`matched_count`、`unmatched_count`、`created_at`

### tasks 任務收件匣

`id`、`title`、`detail`、`status`（`inbox` / `todo` / `ask_boss` / `done`）、`due_date`、`created_at`

### listing_drafts 上架草稿

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | integer PK | |
| product_id | FK products（可 null） | 確認後建立商品 |
| photo_keys | json | R2 物件 key 陣列 |
| reference_text | text | 以圖搜圖找到的資料或網址 |
| notes | text | 重點筆記 |
| weight_g / 尺寸 | | |
| location_id | FK locations | 上架時就指定儲位 |
| generated | json | 各平台的標題、規格、描述 |
| status | text | `draft` / `generated` / `confirmed` / `exported` |

## 5. 模組與流程

### 5.1 訂單匯入（電腦）

```
使用者選擇平台 + 上傳 Excel
  → 瀏覽器端用 SheetJS 解析
  → 依平台設定檔取出欄位，丟棄個資欄位
  → 只送 { 訂單編號, 狀態, 時間, 貨號, 品名, 數量 } 到伺服器
  → 伺服器 upsert 訂單、比對 SKU、寫入庫存異動
  → 顯示結果：新增 N 筆、取消 N 筆、未對應 N 筆
```

### 5.2 批次更新檔匯出（電腦）

```
列出「待更新平台庫存」
  → 使用者勾選平台
  → 依平台範本產生 Excel
  → 下載後手動上傳到平台後台
  → 使用者按「已上傳」→ 更新 last_pushed_stock
```

`last_pushed_stock` 只在使用者確認上傳後才更新，避免下載了卻沒上傳造成數字錯位。

### 5.3 平台轉接層

各平台的差異集中在 `lib/platforms/<platform>/`，每個平台實作同一介面：

```ts
interface PlatformAdapter {
  id: 'shopee' | 'ruten' | 'yahoo' | 'coupang'
  parseOrders(rows: Record<string, unknown>[]): ParsedOrder[]
  buildStockUpdate(rows: StockUpdateRow[]): ArrayBuffer   // xlsx
  buildListingImport?(drafts: ListingDraft[]): ArrayBuffer
}
```

欄位名稱放在每個平台的 `columns.ts` 設定檔。平台改格式時，只改設定檔。
**實際欄位名稱尚未確認**，需先完成驗證清單（下載各平台的匯出報表與批次範本）。

### 5.4 找貨（手機）

搜尋商品名、貨號、條碼 → 顯示儲位、庫存、組合可售量與各部件數量。

### 5.5 出貨核對（手機）

```
選擇訂單（或掃訂單條碼）
  → 逐件掃商品條碼
  → 與訂單品項比對：正確打勾、錯誤立即警告
  → 宅配：掃描列印出來的單號條碼，與系統單號比對
  → 全部吻合才可按「核對完成」
```

### 5.6 上架（手機拍、電腦修）

```
拍照（上傳 R2）→ 貼以圖搜圖資料 → 填重量尺寸 → 選儲位
  → 若為拆賣商品，設定組合關係
  → 寫重點筆記
  → 呼叫 Claude：照片 + 筆記 + 尺寸 + 參考資料 → 各平台標題、規格、描述
  → 使用者檢查修改 → 確認
  → 匯出各平台批次上架檔
```

提示詞放在 `lib/ai/prompts/listing.ts`，版本控管。各平台字數限制放設定檔。

### 5.7 叫貨清單

`stock < safety_stock` 的實體 SKU。一鍵複製成純文字，貼到 LINE 傳給老闆。

### 5.8 任務收件匣

快速新增（一行文字）。下班前可呼叫 Claude，將 inbox 分類成「待辦／要問老闆／已完成」，並產生一則問老闆的彙整訊息。

### 5.9 盤點調整

輸入實際數量 → 系統計算差額 → 寫入 `adjust` 異動。建議固定週期抽盤。

## 8. 資料與隱私原則

1. 程式碼歸開發者，資料歸公司。離職時匯出完整資料（Excel）交還公司。
2. 不存顧客個資；`lib/pii.ts` 列出要丟棄的欄位關鍵字（姓名、電話、地址、Email、收件人等），解析時一律過濾。
3. API 金鑰只放伺服器端環境變數。
4. 每筆庫存變動都可追溯來源。
